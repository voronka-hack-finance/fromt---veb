# front-hack29

Мобильный финансовый дашборд на `Next.js 15`, собранный по Figma-макету. Проект показывает сценарий клиентского интерфейса с акцентом на визуальную подачу: карточки баланса, категории, инвестиции, операции, прогнозы и анимированные графики.

## Что внутри

- `Next.js 15` + `React 19` + `TypeScript`
- `App Router` для маршрутизации
- `CSS Modules` для изолированных стилей
- `Framer Motion` для анимаций и reveal-эффектов
- `Lucide React` для иконок
- Локальные mock-данные без backend-интеграции

## Быстрый старт

### Требования

- `Node.js 20+`
- `npm 10+`

## Маршруты

- `/` - главная панель дашборда
- `/total` - экран общего баланса
- `/income` - экран доходов
- `/investments` - экран инвестиций
- `/operations` - экран операций
- `/operations/trends` - тренды по операциям
- `/operations/bars` - bar-chart представление операций
- `/categories` - экран категорий

## Архитектура

Проект организован послойно, чтобы UI можно было расширять без хаоса:

- `src/app` - роуты Next.js и точка входа страниц
- `src/views` - экранные контейнеры, связывающие маршруты и виджеты
- `src/widgets` - крупные UI-блоки и готовые секции экранов
- `src/shared/data` - mock-данные и демо-состояние
- `src/shared/lib` - форматтеры, chart-утилиты и общие helpers
- `src/shared/types` - общие типы домена
- `src/shared/ui` - переиспользуемые UI-примитивы

### Пример потока данных

1. Route в `src/app/.../page.tsx` рендерит экран из `src/views`.
2. `view` подключает нужный `widget`.
3. `widget` забирает данные из `src/shared/data` и util-функции из `src/shared/lib`.
4. Стили живут рядом с компонентом через `*.module.css`.

## Технические детали

- В проекте настроен alias `@/* -> src/*`.
- Включен `reactStrictMode`.
- Графики отрисовываются через `svg` и локальные хелперы в `src/shared/lib/charts.ts`.
- Данные сейчас статические, поэтому приложение подходит для UI-демо, прототипирования и дальнейшей интеграции с API.

## Как расширять проект

- Новую страницу добавляйте в `src/app/<route>/page.tsx`.
- Экранную композицию держите в `src/views`.
- Сложные визуальные блоки выносите в `src/widgets`.
- Демо-данные и форматирование не смешивайте с JSX, держите их в `src/shared`.
- Если появляется backend, начните с выноса mock-данных из `src/shared/data` в слой запросов или server actions.

## Состояние проекта

Сейчас это frontend-first реализация с хорошей визуальной основой. Для production-готовности следующими шагами обычно становятся:

- подключение реального API и схем данных;
- обработка состояний загрузки и ошибок;
- тесты на форматтеры, chart-утилиты и ключевые экраны;
- accessibility-полировка интерактивных элементов;
- вынос доменной логики из mock-слоя в отдельный data-access слой.
